06 · QUESTIONS 경쟁자에 없는 섹션

고객님께 꼭 여쭙고 싶은 10가지

이 질문들의 답이 프로젝트 성공률을 결정합니다 · 30분 미팅에서 함께 정리해요

🔴 Q1Oracle DB에 어떻게 접근하게 되나요? (상주 / VPN / 파일 전달)

왜 중요한가: 이 답이 아키텍처·배포·일정·비용을 모두 결정합니다. 가장 먼저 확인해야 할 질문.

선택지: A 사내 상주 · B VPN 원격 · C 스테이징 DB 제공 · D CSV/Dump 파일 전달

개발자 권장: B (VPN) — 원격 개발 가능 + 운영 안정성 확보

영향: 답변 지연 시 Phase 1 최대 4주 지연 가능

🔴 Q2"수동 선택"은 단건인가, 묶음인가, 대량인가?

체크박스 다중 선택 또는 필터 기반 일괄이면 비동기 큐 + 진행률 UI 필수. 선택지: A 단건만 / B ~50건 / C ~수천 건

🔴 Q3일·월 발송 예상 규모는? (수백 / 수천 / 수만)

1만 건/일 이상이면 수평 확장 아키텍처(Worker Pool + Redis Cluster) 필수. 인프라 월 비용 15만원 → 50만원+ 변동.

🔴 Q4"즉시 발송"의 SLA? (몇 초 vs 몇 분)

동기 API(<3s)는 외부 API 지연 시 타임아웃 리스크. 비동기 큐 + 진행률 UI 권장.

🔴 Q5배포 환경은 사내 온프레미스인가 클라우드인가?

온프레미스는 설치·운영 문서 2~3주 추가, 클라우드는 IaC로 자동화 가능. 사내 정책 확인 필요.

🔴 Q6카카오 비즈채널 보유 여부? (심사 1~2주)

미보유 시 카카오 심사 1~2주 대기. 발신 프로필 + 템플릿 사전 승인 필수. W01 Day 1 병행 신청해야 일정 안정.

🔴 Q7웹팩스 업체 지정? (엔팩스·비즈팩스·인터팩스)

업체별 API 상이 (REST vs SOAP). 선정 전까지는 ChannelPort 추상화로 대기, 결정 후 1~3일 내 통합.

🔴 Q8이메일 발송 방식? (사내 SMTP vs AWS SES)

AWS SES 권장 — 바운스·수신거부 자동 처리, 월 무료 10,000건, SPF/DKIM 검증 표준 지원.

🔴 Q9외부 API 사용료(알림톡·팩스·이메일) 부담 주체는?

예산 책정 핵심: 클라이언트 계약 / 개발자 정산 / 1,500만원에 포함 중 선택. 포함 시 개발비 실질 -300~500만원.

🔴 Q10관리자 권한을 나눠야 하나요? (1종 / 2종 / 3종+)

RBAC 구성에 따라 권한 화면 3~5일 추가 공수. 1종으로 시작 후 2차에서 세분화하는 것이 경제적.

    private final AuditService auditService;

    /**
     * RSM behaviors.Manager.dispatchBatch()의 application-layer 구현.
     * 사전조건: 모든 pdfIds 존재, 채널별 수신인 최소 1명 확보
     * 사후조건: DispatchJob 생성 + DispatchRecord N건 + Queue 등록
     */
    public DispatchJob dispatchBatch(
            Long managerId,
            List<Long> pdfIds,
            List<Channel> channels,
            DispatchPolicy policy) {

        // 1. 사전조건 검증
        var pdfs = pdfRepo.findAllById(pdfIds);
        if (pdfs.size() != pdfIds.size()) {
            throw new DomainException("일부 PDF 찾을 수 없음");
        }

        // 2. Job 생성 (DispatchJob Object)
        var job = DispatchJob.create(managerId, pdfIds.size() * channels.size());
        jobRepo.save(job);

        // 3. Record 생성 (policy에 따라 분기)
        var records = buildRecords(job, pdfs, channels, policy);
        recordRepo.saveAll(records);

        // 4. Queue 등록 → Worker가 비동기로 처리 (C-1 Collaboration)
        queue.enqueue(job.getJobId());

        // 5. 감사 로그 (cross-cutting concern)
        auditService.record(AuditAction.DISPATCH, managerId, job.getJobId());

        return job;
    }

    private List<DispatchRecord> buildRecords(
            DispatchJob job, List<GeneratedPdf> pdfs,
            List<Channel> channels, DispatchPolicy policy) {
        // BROADCAST: 모든 채널로 동시 발송 (pdf × channels 만큼)
        // PRIORITY: 우선순위 첫 가능 채널 (pdf당 1건)
        return switch (policy.mode()) {
            case BROADCAST -> broadcastMode(job, pdfs, channels);
            case PRIORITY  -> priorityMode(job, pdfs, channels, policy);
        };
    }
